# ADR 0009: Read-only here.now Sites in the Notes list

- Status: accepted for issue #30 implementation
- Date: 2026-10-03 (embedded viewer added the same day)
- Issue: #30

## Verified API contract

The current [here.now list documentation](https://here.now/docs#list) and [OpenAPI description](https://here.now/openapi.json) describe `GET /api/v1/publishes?scope=all`: Bearer authentication, cursor pagination, at most 100 rows per page, and personal, accepted shared, and joined workspace Sites in one response. Rows include `slug`, `siteUrl`, `displayName`, `ownership`, `workspace`, `primaryUrl`, `status`, `currentVersionId`, `updatedAt`, and `contentUpdatedAt`. `contentUpdatedAt` (`scope=all` only) is when the live content last changed, and the list is ordered by it; `updatedAt` also moves on settings changes such as access mode, password, or domain. List rows carry no creation time; `createdAt` is only on the per-Site `GET /api/v1/publish/{slug}` details and on version objects, so showing an added date would cost a request per Site and is not done. The default list omits shared and workspace Sites. `GET /api/v1/accounts` supplies stable account IDs and workspace selectors. `GET /api/v1/publishes/search?q=...&includeShared=1` searches active Sites and returns `nextCursor`, but content indexing excludes PDF text, Office documents, images, audio, and other formats. It includes a shared Site only after the recipient has opened and verified it. The list, therefore, is the inventory source; search results cannot determine which Sites exist.

These statements were checked against the public docs on 2026-10-03. No authenticated live account response was available; a real account smoke test remains before release.

## Behavior

1. Offer an independent here.now connection. Store its API key in a distinct Keychain service, never the Simplenote service. A Simplenote sign-out or account switch does not reassign Sites to another identity. Clearing the here.now connection removes its key and cached metadata.
2. List personal, accepted shared, and joined workspace Sites using `scope=all`. Show each as a read-only row among the Notes, interleaved by the Notes list's current sort and direction (date modified, date added, title, or tags), with the Notes' comparison rules: dates truncated to whole seconds, titles and tags compared case-insensitively, ties broken by title, and a Site placed after a Note it ties with. A Site's modified date is `contentUpdatedAt`, falling back to `updatedAt`; it has no added date. A Site without the sorted date (every Site for date added, and cache rows written before dates were kept until the next refresh) lists after the dated rows in either direction. Sites have no tags. The date columns and the horizontal layout's date show a Site's dates formatted as a Note's are. Rows re-merge when the sort, the Notes, the Sites, or the search changes. Because a Site row can sit anywhere, every row is mapped to its Note through `NVHereNowMixedList` (`noteAtRow:`, `rowForNote:`, `notesAtRows:`, `rowsForNotes:`), never used as an index into the Notes data source.

   Show each Site row with a Site icon and ownership or workspace label. Prefer `displayName`, then `slug`, for the title. Use `primaryUrl` for opening and retain `siteUrl` as the canonical address. The cache key is `(here.now account identity, ownership/workspace identity, slug)`, never a Note ID. Site rows never enter `NVNotesStore`, `NoteObject`, or Simplenote sync.
3. When exactly one Site is selected, view it read-only in an embedded web view in the editor pane, in place of the empty view; nothing loads until a Site is selected, choosing another Site replaces the page, and deselecting it stops loading and discards the page. A header shows the Site title, its address as a link, and an Open in Browser button that is always available. An explicit Open command or Return on a selected Site still opens its URL in the browser. Suppress editing, trash, tagging, export-as-Note, and all Note-only commands while it is selected. No content is cached by the app beyond WebKit's own cache. A browser URL may still require a visitor password or member sign-in; an API key does not grant browser access.

   The viewer's navigation policy: a link to the Site's own host loads in place; a link to any other host, a `target=_blank` or other new-window request, Cmd-click or middle click, a non-`http(s)` scheme such as `mailto:`, and any download open in the default browser and are cancelled in the view. WebKit blocks pop-ups a page opens without a click. Redirects, form posts, reloads, and back/forward stay in place so a restricted Site's sign-in round trip can complete. The view uses WebKit's default persistent website data store, so signing into a restricted Site lasts as it would in a browser; clearing it is the same as clearing Safari-style WebKit website data for the app. The viewer never takes focus on its own: selecting a Site leaves focus in the Notes list or search field, and a page that focuses one of its fields while loading has that focus returned.
4. Refresh on connection and explicit Refresh, and on app activation after a reasonable age threshold. Follow every cursor before replacing the visible snapshot. Preserve the last complete snapshot on transport failure, 401, 403, 429, or partial pagination; mark it stale and show an actionable status. A successful empty inventory replaces the snapshot. Do not treat a failed refresh as evidence that Sites were deleted. Cache metadata per here.now identity for offline list visibility; viewing or opening a Site still needs network access. The viewer's status line says when the page could not load or the saved list may be out of date.
5. Search Notes locally as today. Filter cached Site title, slug, workspace name, and URL locally so results remain predictable offline. A separate opt-in content search could call the here.now search endpoint, with debounce, cancellation, cursor handling, and an explicit partial-index label. Do not silently mix incomplete remote full-text results into the local Notes search.

## Chosen defaults

- Include personal, accepted shared, and joined workspace Sites with `scope=all`.
- Show the selected Site read-only in an embedded web view; open the system browser from Open in Browser, the address link, an explicit Open command, Return on a Site row, or a link the viewer will not load in place.
- Search cached Site metadata locally; do not imply complete content search.
- Keep the last complete snapshot marked stale on refresh failure until disconnect, reconnect, or a complete successful refresh.

`NVHereNowSites` owns read-only requests and a separate JSON metadata cache. Its API key lives in a dedicated Keychain service. `NVHereNowMixedList` combines Site rows with visible Notes without inserting a Site into `NVNotesStore` or Simplenote sync. `NVHereNowSiteViewer` owns the embedded web view, its header, and the navigation policy; `AppController` only shows it for a single selected Site and hides it otherwise. Connection, disconnection and refresh live in the here.now section of Settings ▸ Notes (`NVHereNowPrefsViewController`); the Notes menu keeps only the explicit Open command. The isolated earlier prototype was deleted; it is in git history (commit `c00c582`, `tools/here-now-read-prototype.swift`).

## Validation limits

Fake-adapter tests cover date parsing, interleaving for every sort key and direction with undated Sites and search, row-to-Note mapping with a Site between Notes (showing, deleting, and command gating), cursor pagination, atomic replacement, authentication failure, URL preference, identity, metadata filtering, and Note command gating. Viewer tests load local `file://` pages in a real WKWebView and cover in-place and external navigation, pop-ups, focus, status, and showing the viewer only for a single selected Site. Signing into a restricted Site in the viewer is not verified without a real account. An authenticated account smoke test and manual UI checks for both list layouts, keyboard and context-menu commands, offline display, and browser access to restricted Sites remain before release.
